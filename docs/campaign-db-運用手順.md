# キャンペーンDB 運用手順

作成日: 2026-07-26

## この仕組みが担当する範囲

| 担当 | 内容 |
|---|---|
| **自動（実装済み）** | 残日数の計算 / 「まもなく終了」の判定 / 終了したものをアーカイブへ移す / 並び替え / 掲載が薄いページの noindex / 確認日が古いカードへの注意表示 |
| **人力（週1回）** | 各社の公式ページを見て、`src/data/campaigns.ts` に事実を書く |

日次ビルド（08:07 / 21:07 JST）が回るたびに、上段は全部やり直されます。
データを1回書けば、期限切れは放置しても自動で消えます。

### 一次情報の取り方（2026-07-26 に実測）

| 方法 | 結果 |
|---|---|
| WebFetch（要約モデル経由） | ❌ 項目名が文字化けし、条件が抜け落ちた。使わないこと |
| **実ブラウザで開いて本文を読む** | ⭕️ 段階表・注意事項まで正確に取れた。こちらを使う |

金額と条件を扱う領域で誤った内容を載せると被害が出ます。
一覧ページには条件が載っていないことが多いため、必ず各キャンペーンの個別ページまで開いてください。

## データの書き方

`src/data/campaigns.ts` の `CAMPAIGNS` 配列に追記します。

```ts
{
  id: "sbi-202608-01",              // {companySlug}-{開始年月}-{連番}
  company: "SBI証券",
  companySlug: "sbi",               // /campaign/sbi/ になる
  category: "securities",           // securities | fx | crypto | cfd
  title: "◯◯キャンペーン",          // 公式の表記に合わせる
  summary: "何がもらえるかを一行で",
  maxAmount: 20000,                 // 金額特典が無ければ省略
  conditions: [
    "期間中に総合口座を新規開設すること",
    "エントリーが必要",
  ],
  startDate: "2026-08-01",
  endDate: "2026-09-30",            // 終了日未定なら null
  officialUrl: "https://...",       // 一次情報。必須
  affiliateUrl: "https://...",      // 提携済みなら。無ければ省略
  checkedAt: "2026-07-26",          // 確認した日
  note: "除外条件など",              // 任意
},
```

### 守ること

1. `officialUrl` で実際に確認できた内容だけを書く。他サイトからの転記はしない
2. 読み取れなかった項目は空欄にする。推測で埋めない
3. `checkedAt` を必ず更新する。14日以上経つとカードに注意書きが自動で出る
4. 終了したものを配列から削除しない（実施履歴として残す）
5. 「一番お得」「おすすめ」は書かない。事実だけ載せる

### 対象を絞る

全社の全キャンペーンは追えません。**投資失敗録の読者に関係する口座開設系**に絞ります。

提携の有無で掲載を分けないでください。
2026-07-26 時点で提携済みなのは DMM FX（A8.net）とマネックス証券 FX PLUS（アクセストレード）の2社だけですが、
2社では一覧として成立しません。提携が無い会社も同じ基準で載せ、
提携済みのものにだけ `affiliateUrl` を付けます。

`affiliateUrl` は文脈が合うものにだけ付けること。
たとえばマネックス証券の株式・投信キャンペーンに FX PLUS のリンクを付けるのは誤誘導になります。

## 週次の更新手順

1. 提携済み各社の公式キャンペーンページを開く
2. 新しいものがあれば追記、条件が変わっていれば修正
3. 変更が無かったものも `checkedAt` を今日の日付に更新する
4. `npm run build` が通ることを確認
5. push する

### push が弾かれるときの手順

cron の auto-publish が `logs/x-post-pending.txt` を先にコミットしているため、
push が fast-forward で弾かれることがあります。
未コミットの作業を巻き込まないよう、衝突するファイルだけ退避して統合します。

```bash
git stash push -- logs/x-post-pending.txt
git pull --no-rebase --no-edit origin main
git stash pop
git push origin main
```

### 本番へ反映する

push しただけでは本番に出ません。`daily-publish.yml` は cron と手動発火のみで、
push をトリガーにしていないためです。

```bash
gh workflow run daily-publish.yml --ref main
```

このワークフローが行うのは「Xポスト用テキストのログ追記 → ビルド → Cloudflare Pages へデプロイ」です。
記事の新規公開は行いません。

## 公開前チェックリスト

掲載が2件以上になるまで `/campaign/` は `noindex` のままです（sitemap からも自動で外れます）。
実データを入れて公開する時に、以下を済ませてください。

- [ ] 掲載2件以上あるか（下回ると検索対象に入らない）
- [ ] `/campaign/` への内部リンクをヘッダーまたはトップページに追加したか
- [ ] `affiliateUrl` を入れたカードに広告表記が出ているか
- [ ] 360px幅で横スクロールが出ないか
- [ ] 各社の公式ページと条件が一致しているか（もう一度突き合わせる）
